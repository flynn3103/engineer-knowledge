# Problem-Solving — Professional

Professional problem-solving designs the environment in which many teams make decisions.

## Build feedback systems

Use service objectives, product outcomes, architecture fitness functions, incident reviews, and delivery metrics to reveal problems early. Standardize evidence and decision records, not the solution to every local problem.

## Govern expensive decisions

Classify decisions by reversibility and blast radius. Push reversible decisions close to the team; require broader review for irreversible security, data, or platform commitments. Time-box analysis and identify the evidence threshold for action.

## Improve the system after failure

Postmortems should explain conditions, defenses that failed, detection, response, and durable actions. Track actions to completion and measure recurrence. Avoid “human error” as an endpoint; ask why the system made the action easy and recovery hard.

## Checklist

- Is the outcome measurable and owned?
- Are facts, assumptions, and value judgments separated?
- Which decision is hardest to reverse?
- What is the cheapest evidence that changes the choice?
- How will the organization learn if the decision is wrong?

```text
FRAME -> EVIDENCE -> OPTIONS -> DECISION -> DELIVERY -> OUTCOME -> LEARNING
       preserve dissent | contain blast radius | make reversal possible
```

## Test yourself

1. Design a review path for reversible versus irreversible decisions.
2. Which metrics reveal that teams solve the same incident repeatedly?
3. How do you keep postmortems rigorous and psychologically safe?
4. When should analysis stop and a reversible experiment begin?

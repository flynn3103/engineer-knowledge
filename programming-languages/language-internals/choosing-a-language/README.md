# Choosing a Language

> Choose from workload evidence and operating cost, not syntax preference.

```mermaid
flowchart LR
  Junior[Junior: task fit] --> Middle[Middle: prototype evidence]
  Middle --> Senior[Senior: migration and boundaries]
  Senior --> Pro[Professional: portfolio governance]
```

Evaluate runtime behavior, ecosystem, deployment, safety, interoperability, team skill, and long-term ownership together. A language is “fast” only for a measured workload and “productive” only inside a real delivery system.

| Level | Done when |
|---|---|
| [Junior](junior.md) | You can separate language features from project needs. |
| [Middle](middle.md) | You can run a production-shaped comparison. |
| [Senior](senior.md) | You can plan adoption or migration safely. |
| [Professional](professional.md) | You can govern a language portfolio by outcomes. |

Practice: compare one vertical slice through build, test, deploy, profile, and debug.

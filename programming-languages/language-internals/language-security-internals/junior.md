# Language Security Internals — Junior

Memory-safe languages prevent many out-of-bounds and use-after-free defects, but injection, authorization, unsafe deserialization, and logic bugs remain. Validate at trust boundaries, minimize privileges, and keep secrets out of code and logs.

## Test yourself

1. What does memory safety not prevent?
2. Where is the trust boundary?
3. Why is sandboxing useful?

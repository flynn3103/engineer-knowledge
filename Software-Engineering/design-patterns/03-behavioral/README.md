# Behavioral Patterns

> How objects communicate and collaborate, and who is responsible for what — the largest category, because communication is where complexity multiplies.

## Topics

| # | Topic | What you'll learn |
|---|-------|-------------------|
| 01 | [Chain of Responsibility](01-chain-of-responsibility/junior.md) | Passing requests through a chain of handlers, each deciding to process or forward |
| 02 | [Command](02-command/junior.md) | Turning a request into a standalone object you can queue, log, or undo |
| 03 | [Iterator](03-iterator/junior.md) | Traversing a collection without exposing its internal structure |
| 04 | [Mediator](04-mediator/junior.md) | Reducing chaotic dependencies by routing communication through a central object |
| 05 | [Memento](05-memento/junior.md) | Capturing and restoring an object's state without exposing its internals |
| 06 | [Observer](06-observer/junior.md) | Establishing a one-to-many dependency so observers are notified of changes |
| 07 | [State](07-state/junior.md) | Letting an object alter its behavior when its internal state changes |
| 08 | [Strategy](08-strategy/junior.md) | Defining a family of interchangeable algorithms |
| 09 | [Template Method](09-template-method/junior.md) | Defining an algorithm's skeleton in a superclass, letting subclasses override steps |
| 10 | [Visitor](10-visitor/junior.md) | Separating algorithms from the objects they operate on |
| 11 | [Interpreter](11-interpreter/junior.md) | Representing a grammar as a class hierarchy and evaluating sentences by tree walking |

## How to use this section

Each topic has five depth levels — **junior → middle → senior → professional** — plus an **interview** Q&A bank and hands-on **tasks**. Each topic folder also includes `find-bug.md` and `optimize.md` practice files. Start at your level and climb.

# Changelogs & Release Notes

Use clear release communication so users and operators know what changed and what to do next.

## Learn by level

- [Junior](junior.md) — write a useful entry from a small change.
- [Middle](middle.md) — distinguish changelogs, release notes, and migration guides.
- [Senior](senior.md) — coordinate customer, operational, and security communication.
- [Professional](professional.md) — make release communication a reliable product practice.

## Apply it

1. Record user-visible changes, fixes, and breaking changes.
2. State required action, rollout timing, and rollback impact.
3. Generate drafts from structured changes, then review them.
4. Publish notes when the change is available to the intended audience.

Use the review questions at the end of each guide to confirm understanding.

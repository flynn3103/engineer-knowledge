# Artifact Signing & Provenance

Prove that a release artifact came from the expected source and build process.

## Learn by level

- [Junior](junior.md) — identify artifacts, signatures, and attestations.
- [Middle](middle.md) — sign artifacts and verify provenance in a delivery flow.
- [Senior](senior.md) — set verification gates and trust boundaries.
- [Professional](professional.md) — govern provenance standards across teams and suppliers.

## Apply it

1. Build from a traceable source revision.
2. Attach a signature and provenance attestation to each artifact.
3. Verify the expected identity before promotion or deployment.
4. Reject artifacts that cannot prove their origin.

Use the review questions at the end of each guide to confirm understanding.

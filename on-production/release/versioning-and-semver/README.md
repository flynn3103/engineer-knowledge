# Versioning & SemVer

Use version numbers to communicate compatibility and make releases easy to identify.

## Learn by level

- [Junior](junior.md) — read and create valid versions, including pre-releases.
- [Middle](middle.md) — choose SemVer, calendar versioning, or another policy for a product.
- [Senior](senior.md) — protect compatibility across APIs, clients, and migrations.
- [Professional](professional.md) — set versioning standards that teams can apply consistently.

## Apply it

1. Define what counts as a breaking change.
2. Document the versioning policy beside the release process.
3. Tag every released artifact with an immutable version.
4. Check that consumers can discover upgrade impact before they deploy.

Use the review questions at the end of each guide to confirm understanding.

# Monitoring — Middle

Use RED for request-driven services and USE for resources. Combine server metrics with real-user monitoring and synthetics to distinguish internal health from customer experience.

Alert on symptoms where possible and causes when urgent action is known. Use duration and multi-window logic to reduce noise. Security and usage monitoring need baselines, ownership, and privacy controls.

## Test yourself

1. Which RED signals fit a queue consumer?
2. Why can internal health miss user failure?
3. What makes a threshold noisy?
4. Which security signal requires immediate action?

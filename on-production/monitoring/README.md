# Monitoring

> Know whether a running system is up, correct, fast, secure, and used — and get that signal in front of the right eyes at the right time.

## Topics

| # | Topic | What you'll learn |
|---|-------|-------------------|
| 01 | [Health Monitoring](health-monitoring/junior.md) | Check whether a single instance is alive and functioning. |
| 02 | [Availability Monitoring](availability-monitoring/junior.md) | Aggregate uptime across a fleet and measure it against an SLA. |
| 03 | [Performance Monitoring](performance-monitoring/junior.md) | Track latency, throughput, and saturation of a running service. |
| 04 | [Security Monitoring](security-monitoring/junior.md) | Detect security-relevant events in a running system. |
| 05 | [Usage Monitoring](usage-monitoring/junior.md) | Track how a system is actually used to inform engineering decisions. |
| 06 | [Instrumentation](instrumentation/junior.md) | Emit metrics from application code — counters, gauges, histograms. |
| 07 | [Visualization and Alerts](visualization-and-alerts/junior.md) | Turn metrics into dashboards and route alerts to the right people. |
| 08 | [Synthetic Monitoring and RUM](synthetic-monitoring-and-rum/junior.md) | Measure a system from the outside — scripted probes and real user data. |

## How to use this section

Each topic has four depth levels — **junior → middle → senior → professional**. Start at your level and climb. Health Monitoring is the per-instance building block; Availability Monitoring rolls it up into a fleet-wide, SLA-facing number. Performance, Security, and Usage Monitoring are the other three questions worth asking about a running system besides "is it up." Instrumentation is how all of these get their raw data out of application code, and Visualization and Alerts is how that data reaches a person. Synthetic Monitoring and RUM close the loop by measuring from outside the system, the way a real user experiences it.

# What Is Technical Debt — Middle

## Goal

Classify debt and decide when a shortcut is worth taking.

## Useful taxonomy

- Code and design debt.
- Test, documentation, and knowledge debt.
- Dependency, infrastructure, and architecture debt.

## Decide deliberately

- Estimate the delivery benefit now.
- Identify who will pay interest and how often.
- Record the repayment trigger: traffic, next feature, date, or incident.
- Reject shortcuts that create unacceptable security, safety, or compliance risk.

## Avoid

- Calling every old component debt.
- Assuming a rewrite removes the interest.
- Leaving deliberate debt undocumented.

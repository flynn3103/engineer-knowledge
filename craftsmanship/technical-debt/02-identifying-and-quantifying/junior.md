# Identifying & Quantifying — Junior

## Goal

Make debt visible through everyday evidence.

## Look for signals

- Files that are hard to understand or risky to edit.
- Repeated defects in the same area.
- Long setup before a simple test can run.
- Copy-pasted business rules and unclear ownership.

## Start a useful record

- Describe the problem and user or delivery impact.
- Link the affected code or system.
- State the next likely change that will hurt.
- Estimate effort roughly and name an owner.

## Prioritize locally

Improve debt in code you are already changing when the improvement is small and safe.

# Identifying & Quantifying — Middle

## Goal

Use evidence to find the debt that costs the team most.

## Build a hotspot list

- Find files with high change frequency.
- Add complexity, low test confidence, incidents, and slow delivery signals.
- Investigate the top few; numbers point to questions, not answers.

## Useful measures

- Churn and change failure rate.
- Time to complete changes in an area.
- Test duration, flake rate, and coverage gaps.
- Stale dependencies and unsupported platforms.

## Avoid

- Ranking debt by lines of code alone.
- Treating a static-analysis score as a repayment estimate.
- Measuring without deciding what action a result should trigger.

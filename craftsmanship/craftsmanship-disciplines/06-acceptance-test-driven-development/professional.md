# Acceptance Test-Driven Development — Professional

## Goal

Create a shared executable specification without building a slow, brittle UI suite.

## Team practices

- Run regular three-amigo conversations: product, engineering, and test.
- Keep examples versioned with the feature and review them as product behavior.
- Separate discovery examples from automated regression coverage.
- Publish a living glossary for important business terms.

## Protect the suite

- Test rules through stable APIs or domain interfaces.
- Keep end-to-end checks few, valuable, and observable.
- Remove duplicate scenarios that prove the same rule.

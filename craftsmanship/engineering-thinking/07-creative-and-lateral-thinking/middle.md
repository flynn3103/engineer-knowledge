# Creative and Lateral Thinking — Middle

Use inversion: ask how to guarantee failure, then reverse the causes. Use analogy: find another domain with the same structure, not merely similar vocabulary. Use constraint substitution: remove, tighten, or reverse one constraint and observe new designs.

Example: queue congestion resembles traffic flow. This analogy suggests admission control, lanes, priority, signals, and congestion pricing—but each mechanism must be tested against software realities.

Create a morphological matrix of independent dimensions such as timing, ownership, storage, consistency, and delivery, then combine choices into candidate designs.

## Test yourself

1. Invert “make deployments safe.” What failure recipe appears?
2. What makes an analogy structurally valid?
3. Which constraint could you reverse in a batch system?
4. How does a morphological matrix prevent narrow thinking?
